## How to contribute

Awesome Mac is community-maintained. Contributions are welcome — whether you want to add a great app you discovered, fix an outdated entry, or suggest a new category.

All contributions are made via pull requests on GitHub. Please read the guidelines below before submitting.

<Note>
  By participating in this project, you agree to abide by the [Contributor Code of Conduct](https://github.com/jaywcjlove/awesome-mac/blob/master/docs/CODE-OF-CONDUCT.md).
</Note>

## Contribution process

<Steps>
  <Step title="Fork the repository">
    Go to the [Awesome Mac GitHub repository](https://github.com/jaywcjlove/awesome-mac) and fork it to your own account. If you don't have a GitHub account, [create one](https://github.com/join) first.
  </Step>
  <Step title="Find the right category">
    Open `README.md` in your fork and locate the most appropriate category for the app you want to add. If no existing category fits, new categories are welcome.
  </Step>
  <Step title="Add your entry">
    Add the app entry in alphabetical order within its category. Use the following format:

    ```markdown
    * [App Name](https://app-website.com) - A short, clear description of what the app does. [![Open-Source Software][OSS Icon]](https://github.com/repo) ![Freeware][Freeware Icon]
    ```

    Include only the label icons that apply to the app. Do not add icons that do not accurately describe it.
  </Step>
  <Step title="Update the table of contents">
    If you added a new category, update the `Contents` section at the top of `README.md` to include it.
  </Step>
  <Step title="Open a pull request">
    Commit your changes with a clear, descriptive title and open a pull request. If your diff is hard to follow, annotate your PR to explain what you did.
  </Step>
</Steps>

## Pull request guidelines

Please ensure your pull request follows these rules before submitting:

- Search previous suggestions to confirm your entry is not already listed.
- Make sure each item is genuinely useful and high quality.
- Create individual pull requests for each suggestion — do not bundle multiple unrelated additions.
- Use [title-case (AP style)](http://titlecapitalization.com) for app names in the format `[App Name](link)`.
- Add entries in alphabetical order within the relevant category.
- Check spelling and grammar carefully.
- Make sure your text editor is configured to remove trailing whitespace.
- The pull request and commit should have a clear, useful title.

## What makes a good submission

A good submission adds an app that is:

- **Genuinely useful** — it solves a real problem or meaningfully improves a workflow.
- **macOS-specific or macOS-optimized** — it works well on Mac, even if cross-platform.
- **Accurately described** — the description is concise and factual, not marketing copy.
- **Properly labeled** — open source, freeware, App Store, and native app icons are only applied when accurate.

<Tip>
  If the app is open source, always include the Open Source icon linking to the source repository. This is one of the most valued attributes in the list.
</Tip>

## Available categories

The list currently covers the following top-level categories. Add your submission to the most relevant one:

<AccordionGroup>
  <Accordion title="Reading & Writing">
    Text editors, office suites, markdown tools, note-taking apps, journaling, writing tools, e-book readers, RSS readers, and PDF tools.
  </Accordion>
  <Accordion title="Developer Tools">
    IDEs, developer utilities, regular expression editors, API development tools, network analysis, hybrid app frameworks, version control, virtualization, databases, and terminal apps.
  </Accordion>
  <Accordion title="Design & Product">
    Design tools, prototyping and mind-mapping tools, screenshot tools, screen recording, and related utilities.
  </Accordion>
  <Accordion title="AI Tools">
    Applications focused on AI-assisted productivity, writing, coding, and other AI-powered workflows.
  </Accordion>
  <Accordion title="Communication">
    Collaboration and team tools, email clients, and file sharing apps.
  </Accordion>
  <Accordion title="Audio & Video">
    Audio recording and processing tools, video editors, media players, and download managers.
  </Accordion>
  <Accordion title="Productivity & Utilities">

  </Accordion>
  <Accordion title="Security & Network">

  </Accordion>
  <Accordion title="Other">

  </Accordion>
</AccordionGroup>

## Reporting pirated software sites

<Warning>
  Awesome Mac does not support piracy. If you find a website that distributes pirated Mac software or cracks, please report it by opening an issue on GitHub. We actively maintain a blocklist of known pirated software download sites.

  [Report a pirated software site](https://github.com/jaywcjlove/awesome-mac/issues/17)
</Warning>

## Updating your pull request

A maintainer may ask you to edit your pull request before it is merged — typically to fix spelling errors or to bring it in line with the list's guidelines. See this [guide on amending a pull request](https://github.com/RichardLitt/knowledge/blob/master/github/amending-a-commit-guide.md) if you need help making changes to an existing PR.
